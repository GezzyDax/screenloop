# Шаблоны телевизоров

[English](tv-templates.md) | **Русский**

Профиль телевизора в Screenloop — это обычный `.toml`-файл, а не код. Чтобы добавить поддержку своей модели, не нужно править Python и ждать релиза: положили файл — работает.

DLNA-рендереров сотни, и у каждого свои потолки по битрейту, разрешению и профилю H.264. Проверить их все мейнтейнеры физически не могут — телевизор есть только у того, кто им пользуется. Поэтому подобрать рабочие настройки для конкретной модели можете только вы, а формат сделан так, чтобы это не требовало навыков программирования.

## Откуда Screenloop берёт шаблоны

| Каталог | Что там | Можно менять |
|---|---|---|
| `screenloop/builtin_templates/` | Пять встроенных шаблонов, поставляются с приложением | нет |
| `<data_dir>/profiles/` | Ваши и установленные из каталога сообщества | да |

Оба каталога читаются при старте и сливаются в один список. Имя файла без `.toml` — это идентификатор шаблона (`sony_bravia.toml` → `sony_bravia`). Идентификатор именно из имени файла, а не из поля внутри: так расположение файла на диске всегда авторитетно.

Свой шаблон не может перекрыть встроенный: файл с совпадающим именем будет отклонён с ошибкой в логе.

## Как добавить шаблон

**Через панель** (Шаблоны → Добавить шаблон) — загрузить `.toml` файлом или импортировать по ссылке. Шаблон подхватывается сразу, перезапуск не нужен.

**Руками** — положить файл в `<data_dir>/profiles/` и перезапустить сервис. В Docker это `/data/profiles` внутри тома `screenloop-data`:

```bash
docker cp sony_bravia.toml screenloop:/data/profiles/
docker restart screenloop
```

**Из каталога сообщества** — включить `SCREENLOOP_COMMUNITY_CATALOG_CHECK=true`, после чего в панели появится список шаблонов, присланных другими пользователями. По умолчанию выключено: без флага Screenloop не делает ни одного исходящего запроса. Импорт по ссылке и загрузка файла от этого флага не зависят.

## Формат

```toml
name = "Sony Bravia X-series"
match = ["sony", "bravia"]
priority = 0
mime_type = "video/mp4"
dlna_protocol_info = "http-get:*:video/mp4:DLNA.ORG_OP=01;DLNA.ORG_CI=0;DLNA.ORG_FLAGS=01700000000000000000000000000000"
probe_port = 52323

[ffmpeg]
video_codec = "libx264"
h264_profile = "high"
h264_level = "4.1"
audio_codec = "aac"
audio_sample_rate = 48000
add_silent_audio = true
max_width = 1920
max_height = 1080
target_width = 1920
target_height = 1080
exact_frame = true
fps = 30
crf = 22
maxrate = "12000k"
bufsize = "24000k"
audio_bitrate = "160k"

[meta]
author = "ваш-github"
tested_on = "Sony Bravia XR-55A80L, прошивка PKG6.7370"
notes = "Без строгих 30 fps картинка дёргается"
```

### Верхний уровень

| Поле | Обяз. | По умолчанию | Что означает |
|---|---|---|---|
| `name` | да | — | Человекочитаемое название, показывается в панели. |
| `match` | нет | `[]` | Слова, по которым шаблон подбирается автоматически. Сверяются с производителем, моделью и именем устройства из ответа DLNA — в нижнем регистре, по вхождению подстроки. |
| `priority` | нет | `0` | Кто проверяется раньше при совпадении нескольких шаблонов. Больше — раньше. |
| `mime_type` | нет | `video/mp4` | MIME, который сообщается телевизору. |
| `dlna_protocol_info` | нет | подставляется автоматически | Строка `protocolInfo` в DIDL. Нужна старым телевизорам, которые требуют явный `DLNA.ORG_PN`. |
| `probe_port` | нет | `9197` | TCP-порт для быстрой проверки «жив ли телевизор». |

Про `probe_port`: он используется **только** как предварительная проверка доступности перед опросом. Ни SSDP-поиск, ни отправка команд от него не зависят. Ошиблись — максимум один цикл телевизор покажется офлайн, после чего Screenloop найдёт его заново обычным SSDP. Поэтому поле необязательное, угадывать точно не требуется.

### Секция `[ffmpeg]`

| Поле | Обяз. | По умолчанию | Что означает |
|---|---|---|---|
| `video_codec` | да | — | Только `libx264`. |
| `audio_codec` | да | — | Только `aac`. |
| `max_width` | да | — | Максимальная ширина, 320–3840. |
| `max_height` | да | — | Максимальная высота, 240–2160. |
| `fps` | да | — | Частота кадров, 1–60. |
| `crf` | да | — | Качество, 0–51. Меньше — лучше и тяжелее. 22 — разумная отправная точка. |
| `maxrate` | да | — | Потолок битрейта, например `"12000k"`. |
| `bufsize` | да | — | Размер буфера, обычно вдвое больше `maxrate`. |
| `audio_bitrate` | да | — | Битрейт звука, например `"160k"`. |
| `h264_profile` | нет | `high` | `baseline`, `main` или `high`. Старые телевизоры не переваривают `high`. |
| `h264_level` | нет | `4.1` | Уровень H.264. |
| `audio_sample_rate` | нет | `48000` | Частота дискретизации звука. |
| `container` | нет | `mp4` | Контейнер. |
| `add_silent_audio` | нет | `true` | Добавлять тишину в ролики без звуковой дорожки. Многие телевизоры отказываются играть видео вообще без аудио. |
| `target_width` | нет | `max_width` | Точная ширина кадра при `exact_frame`. |
| `target_height` | нет | `max_height` | Точная высота кадра при `exact_frame`. |
| `exact_frame` | нет | `false` | Приводить каждый ролик к одному размеру кадра, добавляя чёрные поля. Помогает телевизорам, которые спотыкаются на смене разрешения между роликами плейлиста. |

### Секция `[meta]`

Необязательная и чисто описательная — на воспроизведение не влияет. Сюда стоит записать модель и прошивку, на которых шаблон проверен: это главное, что нужно другим людям с таким же телевизором.

## Как подобрать настройки под свой телевизор

1. Скопируйте `generic_dlna` как отправную точку и переименуйте файл под свою модель.
2. Впишите `name` и `match` — производителя и линейку. Посмотреть, что телевизор о себе сообщает, можно на странице **Телевизоры** после сканирования.
3. Попробуйте как есть. Если играет — вы закончили.
4. Не играет — снижайте требования по одному шагу за раз:
   - Картинки нет, звук идёт → `h264_profile = "main"`, затем `"baseline"`, `h264_level = "4.0"`.
   - Тормозит и подвисает → уменьшайте `maxrate` и `bufsize` (например, `8000k` / `16000k`).
   - Не тянет 1080p → `max_width = 1280`, `max_height = 720`.
   - Первый ролик играет, второй нет → `exact_frame = true`.
   - Ролик без звука не запускается → `add_silent_audio = true`.
5. После каждой правки перезалейте шаблон и пересоберите транскод ролика на странице **Транскодирование**: настройки ffmpeg входят в имя файла кэша, так что старая копия сама не обновится.

## Проверка ошибок

Шаблон проверяется при загрузке и при импорте. Ошибки возвращаются списком с указанием конкретного поля — вида `ffmpeg.crf must be between 0 and 51`, а не абстрактным сбоем. Битый шаблон никогда не попадает в работу: при старте он пропускается с записью в лог, при импорте — отклоняется, файл не сохраняется.

Ограничения, о которых стоит знать заранее:

- Идентификатор (имя файла) — только строчные латинские буквы, цифры и `_`, до 40 символов.
- Размер файла — до 16 КБ.
- `video_codec` и `audio_codec` — по белому списку. Строка команды ffmpeg собирается списком аргументов без shell, так что подставить туда команду нельзя; белый список нужен, чтобы сломанный шаблон не приводил к тихо неправильному результату.

## Как поделиться шаблоном

Если вы подобрали рабочие настройки для телевизора, которого нет в списке — пришлите шаблон в репозиторий сообщества [screenloop-tvs](https://github.com/GezzyDax/screenloop-tvs) через pull request. Заполните `[meta]`: модель, прошивка, что именно пришлось поменять относительно `generic_dlna`. Ваша модель есть только у вас — это самый полезный вклад в проект.
